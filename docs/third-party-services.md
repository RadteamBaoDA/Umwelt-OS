# Services and data flows

Draft inventory, updated 21 October 2026. This is a code and configuration review, not a record of live traffic, a license grant, or provider acceptance. **Implemented** means a route or adapter exists; **configured** means the operator has supplied credentials and enabled it; **runtime verified** needs separate live evidence. No optional remote provider is assumed configured or runtime verified here. Recipients may retain data under their own terms; their retention periods are unknown to this project.

In the table, **received** is content the instance obtains from the named service, and **sent** is an application payload it transmits. Every outbound request also exposes network metadata such as source IP, destination, time, headers and TLS/DNS information to the recipient and the host/network operators; this metadata is separate from the payload listed. Provider credentials, when required, travel in the provider's required header, URL or authorization exchange. The operator must review current provider terms and permissions before activation.

## Endpoint and activation evidence

[RequestPolicy and PrivacySettings](../core/model_gateway/schemas.py) bind remote reasoning, embeddings and search to explicit permissions and destination allowlists. [Gateway transport](../core/model_gateway/client.py) sends the selected capability payload after fresh authorization. The endpoint operator receives the network request. An aggregator or custom gateway may separately disclose it to the chosen downstream model operator; recording just the gateway brand does not identify that downstream recipient. The deployment operator must record both names, endpoint/model routes, current terms and any transfers before activation. This inventory does not infer a downstream provider from a model-name string.

[SearXNG requests](../modules/chat/web_search.py) go to the configured instance. SearXNG is itself a recipient; its configured upstream search engines are additional potential recipients. This repository does not manage or inspect that instance's engine configuration, upstream queries, request headers or logging. The operator must obtain that configuration and add those actual recipients. Ollama/LM Studio are local only when their selected endpoints and infrastructure are local; a remotely hosted instance exposes the same capability inputs to its host.

For sources, the [catalog](../modules/connectors/catalog.py), [dispatch](../modules/connectors/collection.py) and the linked adapter together establish implementation; catalog labels alone do not establish working collection. "Configured" requires the actual deployment's enabled source/settings and required credentials, which were not inspected here. No row is verified active. Gmail, Calendar and Drive remain unsupported content integrations; Google login consent authorizes identity sign-in only, without their collection scopes.

## Local retention and deletion evidence

Each row links to the relevant group below. These describe code behavior and limitations, not a runtime erasure acceptance result. Unless a specific TTL is stated in the linked source, this repository establishes no fixed local retention deadline. Every remote recipient's logging, training use, retention, backups and deletion outcome remain unknown here and require its current terms and operator confirmation.

### Models

Model inputs can originate from durable [conversations and copied evidence](../modules/chat/erasure.py), [agent runs](../modules/agents/erasure.py), [memory](../modules/memory/erasure.py), [documents/vectors](../modules/knowledge/documents/erasure.py) and [search indexes](../modules/search/erasure.py). Those records remain until their supported deletion/retention controls or account cleanup remove them. [Retention settings](../modules/settings/models.py) govern configurable agent-trace retention while raw/document history has no universal TTL. [Settings erasure](../modules/settings/erasure.py) removes stored account provider configuration/credentials. Requests already disclosed to a gateway or downstream recipient cannot be recalled by deleting these local rows. Host environment keys are outside account deletion.

### Search

[Web search](../modules/chat/web_search.py) can cache results and copy selected results into conversations; [auxiliary cleanup](../core/auth/deletion_auxiliary.py) removes the account's search-cache namespace, and [Chat erasure](../modules/chat/erasure.py) removes durable local evidence. Search providers and SearXNG's upstream engines may retain their own copies; no deletion API or retention promise is established by the search adapter.

### Identity

[Auth models](../core/auth/models.py) store password/session hashes and optional Google issuer, subject and email. [Acceptance](../core/auth/deletion_routes.py) disables the account and revokes sessions; [finalization](../core/auth/deletion_worker.py) deletes local identities after required cleanup. Account 1 retains only a sanitized disabled bootstrap tombstone to prevent public setup takeover. A content-free [status receipt](../core/auth/deletion_models.py) remains through seven days after successful completion; failed operations retain authority for retry. OAuth provider records and existing browser/downloaded copies require separate handling. See the [host recovery procedure](development.md#recovering-erased-bootstrap-administration).

### Content

Feed, news, research, economic, weather, hazard, repository, Telegram and custom ingestion results may become originals, observations, documents, provenance, chunks, graph/index data, copied chat evidence and derived outputs. See [Sources](../modules/sources/erasure.py), [Connectors](../modules/connectors/erasure.py), [Ingestion](../modules/ingestion/erasure.py), [Documents/raw files](../modules/knowledge/documents/erasure.py), [Observations](../modules/knowledge/observations/erasure.py) and the [cleanup coordinator](../core/auth/deletion_cleanup.py). Account cleanup removes supported local originals/derivatives with peer-reference checks; merely disabling a connector does not erase its imported history. [Connector remote cleanup](../modules/connectors/erasure.py) handles supported GitHub grant revocation and n8n-owned resources, preserves peer credentials and fails the required stage on unresolved cleanup. Public publisher content, upstream accounts, source services' logs and provider-managed copies are not deleted by removing a local import.

### Unsupported

Gmail, Calendar and Drive have no implemented content adapter or imported-content retention through those catalog entries. This does not describe identity data collected separately by Google sign-in or content the operator imports through a generic connector.

### Media

[Media lookup/proxy](../modules/chat/media.py) fetches selected media and validates time-bound media tokens. Returned metadata or URLs may persist in chat/UI evidence covered by [Chat erasure](../modules/chat/erasure.py); externally fetched media, network/browser/proxy caches and the upstream hosts' access records follow their respective configuration. Account deletion cannot remove exported screenshots or another device's history.

### Telemetry

[Langfuse export](../core/langfuse_export.py) keeps a bounded in-process queue (32 spans), with no persistent exporter spool in that module. It exports model identity, timing, success, token counts and correlation identifiers, excluding prompt/document/completion bodies. Local log files and already queued/sent metadata are distinct from account content tables; host logs and Langfuse retention need operator/provider handling. Neither enabling the exporter nor deleting an account establishes removal from Langfuse.

### Tools

[MCP/tool erasure](../modules/tools/erasure.py) removes stored connections, credentials, grants and browser evidence; [Automation erasure](../modules/automations/erasure.py) removes durable workflow/action records. A remote MCP server or approved webhook receiver receives the authorized inputs and owns its resulting logs/side effects; local erasure does not reverse an external action. [Host webhook profiles](../modules/tools/webhook.py) are secret-free environment configuration (fixed URL/CIDR/enablement), retained by the host rather than erased with an account.

### Database

PostgreSQL/pgvector are deployment-controlled persistence, not evidence of disclosure to PostgreSQL's or pgvector's vendors. The [owner registry and coordinator](../core/auth/deletion_cleanup.py) and [bounded SQL primitives](../core/erasure_sql.py) cover declared domain tables; [Auth finalization](../core/auth/deletion_worker.py) removes identity/workspace last. WAL, database snapshots, replicas and physical backups need separate host retention/restore handling. Installing a store does not identify its hosting operator or prove physical erasure from backups.

### Cache

[Auxiliary cleanup](../core/auth/deletion_auxiliary.py) removes recognized account/workspace Redis namespaces, OAuth state and [Agent checkpoint pages](../modules/agents/account_checkpoints.py) under their owner contracts. Deployment-wide capacity leases and anonymous IP counters are deliberately separate operational state; their expiry/configuration is defined by the owning component. Redis persistence files, host snapshots and logs require operator handling. Redis installation does not disclose data to Redis's vendor by itself.

### Graph

[Temporal graph erasure](../modules/knowledge/temporal/erasure.py) targets SQL-owned exact partition IDs and verifies absence before progressing; required graph failures must block completion. [Temporal SQL records](../modules/knowledge/temporal/erasure.py) are removed through module-owned cleanup. Neo4j hosting, transaction logs and backups are deployment-controlled and require separate retention handling; installation does not establish disclosure to Neo4j's vendor.

The [destination fence contract](../modules/knowledge/temporal/graph_fence.py) retains a permanent technical `UmweltPartitionFence` deletion marker containing only an opaque partition UUID and an erased flag. It has no `group_id`, source content, account ID or workspace mapping. Both adapter writes and erasure use this marker to reject a delayed pre-deletion write even after a PostgreSQL lease connection is lost. It is deliberately excluded from graph-content deletion: removing it would permit stale writers to recreate erased content. This narrow safety marker is not a promise about graph logs or provider backups.

Original-file storage uses a [filesystem destination fence](../core/storage_admission.py) independent of PostgreSQL connectivity. Permanent `.storage-fences/<opaque-workspace-UUID>.lock` files contain only a one-byte deletion flag and serialize physical upload/erasure with an OS lock. They hold no account details or source content and survive the originals sweep to prevent stale admitted uploads recreating erased files. Operators must preserve these markers when maintaining or restoring storage; remote filesystems must support the required interprocess locks.

### Automation

n8n receives configured workflow inputs and owns workflow/execution/credential state in its deployment. [Connector cleanup](../modules/connectors/erasure.py) removes account-owned remote workflows/credentials when supported and unshared; uncertain remote operations prevent completion. This does not promise removal of n8n execution history, its host database/backups/logs, or upstream provider copies. The operator must configure n8n's own execution retention and inspect actual enabled workflows/downstream recipients. Installing n8n does not by itself send content to n8n's vendor.

### Host

The actual hosting, DNS, certificate, tunnel/CDN and backup operators are unknown until deployment inspection. [Proxy configuration](../infrastructure/proxy/Caddyfile) and [development/deployment guidance](development.md) describe configuration, not active use or a fixed retention period. Operators must record actual traffic/log/snapshot recipients, locations, configured retention, access and restore procedures. Account cleanup does not remove host environment secrets, provider backups, certificate transparency entries, DNS history or third-party retained copies.
