## Advisory dispositions

1. **Editor identity and guarded transitions:** The editor is keyed by selected source/new-session identity. Source switches, Add connector, Add manual and close flow through the current draft guard. A nonempty replacement secret participates in the discard prompt. A successful Resume consumes the returned active source status.
2. **Request/auth lifecycle:** New connector helpers accept `AbortSignal`. Editor requests share an action lock, request generation, auth generation and abort controller; handlers check ownership after awaited calls before state/cache updates and parent callbacks. Close, parent transition, auth ending and unmount invalidate and abort pending requests. Save-and-enable holds the lock across Save and activation.
3. **Draft/version behavior:** Validation records success only for the submitted source generation, desired revision and draft version. Editor controls are disabled while an action runs. Save acknowledges only the submitted version; refresh preserves a dirty draft instead of applying server state over it. Validation is only available for a known source ID and has no create fallback.
4. **Credential draft handling:** A nonempty unsent secret marks the editor dirty and remains only in component state. Save/validation payloads omit it; activation receives it only for HTTP-header auth. It is cleared on accepted transition, auth ending, incompatible auth binding and successful activation. Credential removal is disabled while the draft is dirty.
5. **REST mapping:** UI provider identity is `rest`; only `createConnectorSource` maps it to source type `api`. Loaded config, defaults, catalog selection and REST controls use `rest` consistently.
