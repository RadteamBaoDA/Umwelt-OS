## Proven gap and owner

`connectors.registry.normalize` produces bounded receipt-shaped records. `ingestion.public.receive_batch` saves batches/SourceObservation/stage/outbox/cursor atomically; `_collect_web_job` does the same for crawl observations. `ingestion.worker.process_ingestion_event` only verifies observation count before reporting success. There is no consumer materializing these observations into document revisions/chunks; document revision producers are manual create/append, file parser and fictional seed.

Scope owner: ingestion processing (P02-T1 durable receipt/stages and P02-T3 normalized RSS/URL/REST mappings), with document owner persistence. P02-T2 file parsing is already a separate real producer. R13.1 later consumes textual/social/research normalization; R14.1 separately owns structured world-data observation mapping. R04 settings, R06 replay, R15 correlation and P04 entity extraction do not absorb this work.

## Minimum implementation

1. **Consumed document command.** Add document-owner `upsert_normalized_document(session, input)` returning detached `{document_id,document_version_id,version_number,created_version,chunk_count}` without committing. Input is validated source ID/generation, provider record ID/version, record hash, observation ID/time, content, bounded title/canonical URL/published time/content type and allowlisted provenance. Ingestion may not import document ORM or fake `DocumentCreate` owner HTTP calls. Existing `has_document_identity` is only a bool; `create_document/append_content` commit internally and cannot implement atomic normalization/retry publication.
2. **Stable identity/revisions.** Use existing document uniqueness `(source_id, external_id)` with source-scoped `provider_id` as external ID. Stable provider/version/hash identifies a normalized observation; persist an idempotent observation→document-version mapping owned by ingestion/documents through DTOs. Identical observations across retry/overlapping batches attach to an existing immutable revision, not a new version or a rollback to an older current revision. Lock source before document; allocate next revision under document lock, not read-then-insert. Provider versions may be opaque: never compare them lexically as time. Retain delayed/conflicting observations as history and use documented provider ordering/observation order with deterministic tie policy for current selection. Changed metadata/provider version needs an immutable provenance revision even if text bytes match; `content_hash` alone is insufficient dedupe identity.
3. **Immutable provenance.** Every produced version carries provider ID/version, original observed time, local collected/received time (distinct), canonical URL/title/published time when supplied, accepted record hash and bounded metadata/provenance. Add owned version provenance storage through a new Alembic revision if necessary; current DocumentVersion has only text/hash/observed/created times and mutable Document metadata cannot prove historical provenance. Existing RSS mapping stores title but drops a distinct item URL/publication/collection time; preserve supplied provider fields in owning connector mappings. Do not infer a URL from every opaque provider ID or relabel publication time as collection time. Unavailable values remain null/unknown. Never include credentials/raw service keys.
4. **Bounded durable stage.** Add a concrete `normalize` stage/work event per accepted textual batch using current IngestionStage/EventOutbox, explicit dispatcher mapping and registered ingestion worker function. Persist progress/observation disposition, source generation and normalization version; process a bounded number/bytes per transaction and resume from PostgreSQL after enqueue loss/worker expiry. Scope all observation reads to its batch/source; validate each record before writes. Use current source/connector fence semantics as appropriate for already accepted data; define the policy once, never silently revive a paused/archived generation. No generic pipeline DSL or second queue. Do not use unmodified `retry_run`, which selects one stage, without updating it to identify/retry the new stage safely.
5. **Chunks and consumers.** Document owner creates immutable chunks using existing `core.chunking.chunk_text`; persist version, chunk rows, observation disposition/progress and pending work event in one transaction. Emit the P04 `document.version.ready` contract only for actual ready nonempty chunks; P04's explicit consumer mapping owns entity work identity. Lexical search sees real current chunks. Existing `search.indexing.index_pending_chunks` polling handles permitted current chunks in the active/queued index generation; use this consumed path instead of a competing vector queue. Semantic/model gating does not turn textual normalization into failure or invented indexing success. If model settings are unavailable, keep receipt/library/lexical behavior and expose embedding/entity extraction gates separately.
6. **Deletion and retry.** `sources.public.lock_source` fences every normalization transaction; compare captured generation, reject archived/deleted data and never recreate purged observations/documents. Pause/reconfigure invalidates obsolete work with visible disposition. Source purge already deletes observations/cancels ingestion via `cancel_and_purge_source_ingestion`; include new progress/stages/work and version provenance. Single-document deletion must invalidate/tombstone the observation's materialization identity so replay cannot recreate it; define retry/new-provider-version behavior explicitly rather than relying on deleted FK rows alone. Compose P04 support cleanup where present. Transient retries resume exact stage/observation identity; schema/auth failures stop visibly; already committed observations stay idempotent after partial-batch failure. Receipt cursor means durable acceptance, not downstream normalization success; never rewind acknowledgment because a later parser/model fails.
7. **Completion reporting.** Run UI/state distinguishes received/normalized/chunked from embedded/entity-extracted; raw receipt success does not claim library readiness. Add the real stage to source run DTO reads (R04 contracts), update literal status consumers deliberately, and bind committed identifier/status notifications to integrated R06 finalizer only after all domain locks/writes/flush. No private payload/source text in replay. Record schema migration parent from actual integrated head, owner contracts, source impact, exact authorized production builds, independent source review and remaining runtime gates.
