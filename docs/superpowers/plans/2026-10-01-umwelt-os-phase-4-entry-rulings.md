## 1. Document evidence/input boundary

Use document-owned detached DTO queries; no new foreign ORM projection exception is needed. Existing `documents.public.get_document/get_version/list_versions` return ORM and remain owner-local. Existing `lock_document_for_extraction`, `set_extraction_status`, `save_extraction` serve file parsing and do not supply P04 evidence input.

Physical document/source-data deletion makes evidence unavailable; no cached excerpt substitutes for deleted content. Background extraction requires a fresh active `sources.public.lock_source` fence, captured generation and `local_only=False`; manual sources are currently local-only and therefore cannot be sent remotely. Owner confirmation does not override that flag.

For extraction, hold the source fence across bounded transport, revalidate input membership/status before sending and publishing, and reject stale generations/deleted inputs. `ModelGateway.before_send` executes before each SDK retry: re-read settings and verify the captured alias/model/version/gateway identity plus current reasoning grant and destination each time. `entities.public.get_entity_refs(session, ids)` is the corresponding bounded detached entity existence/reference query for relationship endpoints and neighbor assembly: `{requested_id, canonical_id, revision, type, name}`. Internal resolution code inside the entity owner may use its own persistence.

## 2. Stable entity evidence membership and confidence

Add **entity-owned evidence memberships**, distinct from `RelationshipEvidence.id` and document/chunk IDs. Minimum record: stable UUID, current canonical entity ID, exact version/chunk identity, extraction identity/candidate key where derived, observed/extracted times and finite confidence in `[0,1]`. Retry uniqueness is on extraction identity/candidate/chunk, so retries do not create fresh memberships. Preserve membership UUIDs when ownership moves during merge/split; multiple historical memberships for one chunk are deduplicated when counting support, not erased merely to enforce entity/chunk uniqueness.

`POST /entities/{id}/split.evidence_ids` means these entity-membership UUIDs. Reject missing, foreign-entity, duplicate, deleted-support or stale memberships. Expose paginated membership DTOs to the split editor and extraction reconciliation. `RelationshipEvidence` alone cannot supply this interface.

Each derived relationship support must identify the source and target entity memberships it asserts (nullable only for genuinely owner-authored facts), in addition to its version/chunk reference. This is consumed by split: selected memberships identify exactly which endpoint/support moves. Alias-derived supports also reference entity memberships. A bare alias `source_id` cannot explain shared support or source purge. Expose public entity-owner commands to validate/create/reassign memberships; relationships do not write entity tables.

Minimum confidence ruling: each derived support has required finite confidence; a derived relationship's confidence is the **maximum remaining support confidence**, recomputed after changes/deletion. This does not claim independent corroboration. Require at least one support; delete unsupported derived relationships in the same deletion transaction. Owner relationships/aliases may have null confidence; do not manufacture `1.0`. Derived aliases have support/confidence, while `confirmed` remains an owner identity decision, separate from model confidence. A sourced alias with multiple supports survives deletion of one support.

Deletion composes owner public cleanup in actual transactions: `documents.public.delete_document` and `sources.worker.process_source_purge` (which calls `documents.public.delete_source_documents`). Remove memberships, derived alias supports and relationship supports for deleted versions/source, recompute confidence, remove unsupported derived facts, and retain genuinely manual corrections/identity. Do not use only the preserved uncalled global `remove_unsupported_derived` sweep. Source rows survive archive/purge, so `ON DELETE SET NULL` is not the cleanup contract. Surviving shared entities must not display deleted-source names/descriptions/aliases/excerpts; keep text only when independently supported or explicitly owner-authored.

## 3. Manual provenance and persistent corrections

Owner write routes obtain `actor_id` from authenticated `AuthSession.owner_id`, not a request assertion. Persist server UTC time, operation, reason (bounded default such as `owner_create` where no freeform reason is supplied), affected IDs/revisions and protected field/identity decisions. `origin=owner` alone is insufficient. Never store token hashes, session credentials or fabricated document evidence. Manual entity/alias/relationship authoring has no document support unless the owner explicitly attaches validated existing evidence.

Extraction never sets `confirmed=True` or overwrites protected owner fields. Resolution requires a namespaced explicit external identity, an unambiguous confirmed alias in its documented scope, or persisted manual correction. Exact/fuzzy names alone produce review candidates. Conflicting identity signals also require review. Durable rejected alias/relationship/entity decisions must suppress recreation during later reconciliation, rather than just deleting a row. Correction records retain identity/decision IDs, not a permanent copy of forgotten source text.

## 4. Merge/split identity and conflict rules

- Merge request retains source `expected_revision` and adds `expected_into_revision` for the target. Lock both entity rows in stable UUID order; refresh/compare both revisions and reject self, missing/deleted target, incompatible type or redirect-loop conflicts with 409. Resolve reads through public `get_entity/get_entity_refs/KnowledgeService`; return requested and canonical IDs explicitly. Writes against redirected IDs return a conflict with canonical ID/revision for owner review.
- Keep the old entity ID as a redirect; increment source/target revisions, protect the target's owner-selected name/identity, and move memberships without changing their IDs. Record manual alias/protected-field/external-identity conflicts; reject unresolved conflicts rather than choosing a name silently.
- Relationship equality is canonical source ID, target ID, type, origin and exact nullable validity bounds. Merge duplicate edges/support by this identity, preserving all distinct source supports. Conflicting owner metadata needs explicit resolution. Preserve duplicate-ID replacement mapping in the correction result for stale views. The draft forbids self edges: reject a merge that would create one with a bounded conflict preview until the owner explicitly removes/resolves those relations; no silent loss of manual facts.
- Split creates a new ID and moves only selected memberships. With endpoint membership bindings, relationship support groups may remain on the old edge or move to a new edge; shared support remains valid on its actual endpoint assignment. Unselected/manual relationships and aliases remain on the original entity unless explicitly selected in a bounded owner command. Mixed or missing endpoint assignment rejects as an explicit conflict; do not guess facts from matching names. Confirmed/manual identity assignment and suppression rules are persisted so the next extraction does not undo the split.
- Large merge/split closure is rejected with a controlled bounded-scope conflict/preview before partial writes; do not silently process an unbounded graph or commit only some memberships. Correction consumers are `entities.corrections`, extraction resolution/reconciliation and the planned merge/split/resolution-review UI.

## 5. Ready-version event, durable extraction and registrations

Choose one consumed version-1 event, **`document.version.ready`**, produced by the document owner after actual ready chunks exist. Payload contains identifiers only: document/version/source IDs and captured source generation (version number optional); no text. Produce in the same transaction as the ready version/chunks. Concrete producer sites: `documents.public.create_document`, `append_content`, successful ready/succeeded `save_extraction` as composed by `ingestion.worker.process_uploaded_file`, and legacy chunk backfill after chunks are persisted. No event for empty upload placeholder, `needs_ocr`, metadata-only edit or unchanged-content append.

`entities.worker.process_document_ready` consumes the event, calls entity-owner `schedule_extraction` to persist the unique work/result identity `(document_version_id, extractor_version, prompt_version)` and executes/resumes that work. Event delivery becomes terminal only with durable entity work disposition; bounded leases, attempts/next-attempt/error and retry recovery live in PostgreSQL. A bounded entity recovery/backfill scheduler selects document-owner ready refs, calls the same command and re-dispatches expired/incomplete work. ARQ loss does not lose identity, output or retry state. Parsing/library/search success is independent of entity extraction failure/gating.

Explicitly add the event→`process_document_ready` mapping in `ingestion.dispatcher.dispatch_pending_work`, register the function and bounded recovery cron in `apps.worker.main.WorkerSettings`. Today unknown types fall through to `process_ingestion_event`, which expects `run_id/stage_id`; a knowledge event without mapping fails integration. Pure `EntityUpdated/KnowledgeChanged` replay notifications must not be sent to that work fallback. Document owner emits the contract through existing durable publication; it does not acquire a cyclic import of entity persistence/worker. Event consumer owns extraction scheduling.

Register actual entity/relationship descriptors in `core.modules.register_modules`, router composition in `apps/api/main.py`, and all owning models in Alembic env. Entities require document/source contracts; relationships require entity/document contracts. Fill consumed events/routes/provides with implemented capabilities, not future tool placeholders. P04-T4 `modules/knowledge/public.py` delegates only implemented DTO methods (`get_entity`, `get_entity_neighbors`, actual document/evidence/search methods as consumed).

**R06 binding pending:** bind all new P04/domain-deletion producers to the actual integrated typed append/finalize API, event names and query invalidation map after R06 review. Finish all domain writes/locks/flush first; replay head allocation is the final commit suffix with no HTTP or new conflicting domain locks afterward. Browser replay and ARQ extraction dispatch have distinct records/consumers. This ruling does not invent the R06 function signature or authorize edits to its active tree.

## 6. Graph continuation and real frontend/search consumers

`get_neighbors` enforces the public contract, not just HTTP limits: default **50 total nodes**, hard **100 including focus**. Minimum safe page scans at most `limit-1` ordered relationships (`created_at DESC,id DESC`) plus one lookahead and materializes only compact endpoint refs; edges are independently capped at 100. Cursor is opaque and scoped to canonical focus, filters and ordering; malformed/cross-focus cursor is 422. It encodes the last scanned relationship, not node count. Include `truncated/next_cursor`; no unbounded aliases/evidence lists inside graph nodes/edges. A graph page may contain fewer unique nodes due to parallel edges. Full evidence is a separately paginated panel (default 20, hard 50 per page).

The client deduplicates by stable node/edge ID and enforces **100 accumulated visible nodes** across expansions, with a bounded edge set. It stops expansion at the cap and retains a visible continuation/reset action; the keyboard relationship list can continue independent pages. Do not skip undisplayed server rows by advancing the cursor beyond the accepted client page. The focus-only/cap-full state makes no expanding request; normal requests use node budget at least 2. Concurrent writes do not promise frozen graph snapshots; an updated entity/knowledge notification refetches/reset continuation using final R06 behavior.

Concrete consumers: planned `relationship-graph.tsx`, keyboard relationship list, `entity-detail.tsx`, `resolution-review.tsx`; `modules/knowledge/public.py` delegates the same bounded DTO. Evidence link uses existing `/knowledge/documents/{document_id}?version={version_number}#cited-revision`, backed by authenticated `GET /documents/{id}/versions/{number}` and `DocumentDetail.citedVersion`; no nonexistent chunk navigation claim.

Current frontend `core/module-registry.ts` is a destination registry, **not a search-provider registry**. Backend `search.public.search` and `SearchHit` are document-only; `entity_refs` defaults empty and does not make an entity provider. P04 must add a small consumed entity-result provider/read contract and typed result handling in actual search API/UI; preserve existing document responses/cursors and their evidence policy. Entity results with no evidence show owner provenance, not a fabricated document citation. Add entity detail/list to detail/command destinations, with locales, never main navigation. Document-hit entity annotations consume the entity membership DTO, not private entity persistence. Exact entity/search DTO extension is resolved in T4 source review, not claimed already registered.

### T2 source fence and blocked recovery ruling

Claim the PostgreSQL lease durably, then hold the actual source row lock followed by document lock in the execution transaction before reading input or sending it. Revalidate active source, captured generation and exact current ready version. Retain those locks through bounded transport, validated evidence publication and the sole head-last replay commit. A short separate callback session cannot replace this source fence. Check actual unexpired lease ownership before publication and terminal/error writes; reclaimed workers cannot publish.

Permanent document/source-generation/local-only/input-limit blocks do not retry on a timer. Configuration/capability blocks use the existing bounded recovery with one durable nonsecret dependency fingerprint (current configuration, alias/model/version/gateway and actual capability observation). Requeue only after that dependency changes and current permission, endpoint and structured capability are eligible. Preserve captured source generation; recovery must not silently rebind stale work. No separate retry service or UI is required. Initial T2 build predates these repairs and does not validate them; the prescribed postrepair build and formal review remain required.
