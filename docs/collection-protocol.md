## 3. Scope and transaction lock order

User `request_collection` receives WorkspaceContext and verifies owner role, source workspace, active account/membership and expected connector revision. Worker receives only request UUID, loads its durable actor/workspace/fences, constructs InternalJobScope, then invokes W2 public admission. Scope from a bearer body or arbitrary worker argument is not authority. Nonbootstrap gating, privacy/module state and backup/maintenance admission remain active.

Use this order for every request admission, renewal, pre-send, acceptance and recovery transaction:

1. Register existing backup admission in its separate short transaction, before domain locks.
2. W2 auth accounts/session -> workspace -> membership/grants, using owner public helpers. No later lock can call an earlier helper. Discover all IDs without locks, then reread under locks.
3. Source public lifecycle lock -> ConnectorProvisioning -> relevant connector/native credential/binding rows in their existing deterministic order -> SourceIngestionState. Preserve stricter GitHub grant/hint and Telegram proof local ordering rather than opening a second reverse path.
4. Connector schedule/request rows, then ingestion receipt/batch/run/owner journal rows. Same-workspace paths serialize through workspace; request lookup before this phase is nonlocking identity discovery only.
5. Quota windows in lexicographic complete-key order when sending, then quota send/debit rows; global slot rows ascending slot_id, acquired with NOWAIT/SKIP LOCKED during admission. A busy earlier capacity row defers promptly, without holding a transaction while waiting on remote work.
6. Owner outboxes and scoped replay head last, followed by one commit. Existing owner helpers must be made flush-only for composition and must not secretly commit or acquire earlier locks.

No operation holding a slot/quota lock may acquire another workspace/source lock. Expired-slot scans read identities first; each old occupant is recovered in its own workspace transaction. A new workspace never recovers an old occupant inline while holding its own locks. Fairness selection updates consideration metadata in a separate short scheduler-only transaction and releases those locks before scope/domain work. Such selection is not admission and conveys no source content permission.

Ingestion owns final commit and source-state mutation. Connectors exports narrow detached read/lock/flush hooks for request admission/settlement; ingestion does not import Connector ORM. Conversely, connectors never mutates SourceIngestionState or receipt ORM. This is a finite extension of current public seams, not a generic callback/plugin transaction framework. Factor existing commit-bearing functions into owner-private transaction-local operations plus existing public wrappers; no naked `commit=False` flag that lets an arbitrary caller forget required replay/settlement.

## 4. Admission, send and atomic acceptance

**Admission:** under the locks above, check receipt first, then live authority and captured generation/config/backend/template/credential/terms revisions, applied readiness, correction gate, available_at/provider deadline and request queued state. Check SourceIngestionState is free through its owner API; generic RSS/REST/MCP gain this owner API without acquiring trusted provider metadata privileges. Reserve an available slot and the existing source collection lease in the SAME transaction. Set request running, increment attempt once, set fresh admission/source tokens, expires_at=database now+120s, attempt deadline=now+90s for REST (retain stricter reviewed provider budgets). Commit before any network call. Source busy/workspace busy/quota precheck defer without incrementing attempt. An admitted attempt counts even if it crashes before first HTTP; this avoids endless crash retries. A quota race after admission can consume that one admitted attempt but never makes an unauthorized send.

**Renewal:** every20s independently of response streaming, revalidate full scope/claim/revisions and exact request/slot/source token; renew only a currently unexpired slot to now+120s and extend matching source lease via ingestion owner policy. Do not extend absolute execution deadline. Failure stops new sends and rejects new acceptance. Never renew a lease_run_id through the collection token API.

**Every physical send:** perform a short fresh authorization transaction, check exact admission and source ownership, endpoint/credential/terms revision, execution deadline and provider deadline, then debit ALL applicable durable quota windows atomically and commit before transmission. Revalidate immediately before headers if transport setup can delay; two checks of the same in-process send do not debit twice. Each page, connection-level retry, provider fallback or repeated send obtains a NEW send_id/debit; disable hidden automatic retries and redirects. A consumed send permit is never replayable after a crash. Debit ambiguity is conservative: a crash after debit but before wire send loses budget, never refunds or authorizes another physical send with that ID. Exhausted budget leaves used counters unchanged, records the defer deadline, and performs no provider I/O. 429/Retry-After updates all applicable persisted deadlines; local backoff never shortens it.

**Post-I/O acceptance:** the ingestion-owned API reacquires the same full lock order; verifies scope, tokens, expiry, source/config/backend/credential/terms, provider proofs, cursor-before and payload bounds. It first resolves request receipt identity; an authorized identical replay returns that receipt without rerunning collection or changing a successor's lease. New acceptance creates/reuses the valid batch and ingestion run, stores observations/outbox, advances cursor only through Ingestion, transfers collection lease to run ownership if processing is needed, inserts request receipt, flushes Connectors request succeeded/no_changes and slot release, then commits replay ONCE. Transaction failure means none of these changes is accepted. A request can have one terminal acceptance receipt, regardless of content-hash replay.

Generic no-change/HTTP304 follows the same atomic path, has no fake data, and preserves last-good observations. ETag/Last-Modified are source+config-revision scoped ingestion acknowledgement state, committed only with acceptance; reserve two nullable bounded fields plus their connector_revision on SourceIngestionState through I. REST cap with more data and no exact durable continuation is `collection_incomplete`, no cursor advance, never no_changes. Provider continuation loops that currently accept multiple native pages must emit one bounded collection request per accepted page/segment, with a new continuation request only after the prior request is terminal; do not reuse a terminal request ID for another receipt. Fair dispatch applies to continuation too.

## 5. Recovery and retry, before any refetch

For every queued/running recovery identity, in a fresh admitted transaction:

1. Resolve ingestion receipt by request UUID first. Matching receipt makes the request terminal/reconciles the pointer and releases only its matching residual slot; no provider fetch. Normally atomic commit means pointer repair is unnecessary, but receipt-first tolerates response loss and proven legacy repair. If source was deleted or actor disabled, internal retained-lineage cleanup may settle bookkeeping without exposing protected payloads; it must not fetch as that actor.
2. No receipt + current running slot/source lease: leave running; do not enqueue a second executor. Lost wake/ARQ acknowledgement does not establish failure.
3. Expired slot: fence/clear that exact slot occupant under its old workspace. Mark the running attempt expired. Source collection ownership may still live for15minutes. Conservative recovery waits; accelerated recovery calls an ingestion-owned exact-token revoke after proving expired admission and absence of receipt. Never clear a different collection token or any ingestion-run lease. An invalid ownership row with missing expiry is action-required, not assumed free.
4. Once source collection ownership is released, recheck current revisions and authority. If changed or paused/deleted, cancel old request. Otherwise retry only transient network/429/5xx, set queued/available_at and clear active admission. Obtain NEW admission and source tokens at dispatch. At attempt5 failure is terminal; next regular request is permitted only after persisted provider deadline and normal schedule. No other layer multiplies five by its own retry loop.
5. Credential/schema/terms failures fail the request and persist the source gate with the relevant revision dimensions. Manual and regular calls return the same bounded action-required condition before I/O. Re-enable only when each applicable failed dimension is corrected AND fresh validation/eligibility succeeds; an unrelated revision bump or old credential operation replay cannot clear it. Keep the old request failed; corrected work creates a new UUID.

Slot release after acceptance frees network capacity while ingestion-run lease remains independently owned. Expired admission cannot guarantee cancellation of already-sent external HTTP; only two current admitted collection jobs and one per workspace are guaranteed. Old physical work may overlap after a crash/timeout but cannot publish accepted results or advance cursor. Document this precise boundary without claiming strict cancellation of remote requests.

## 6. Fair bounded scheduler and n8n recovery

Every15s, use at most50 workspace consideration turns ordered by persisted last_considered_at then UUID. Choose each workspace's oldest eligible pending request or due native source, using oldest last_considered_at first, then last_dispatch_at/next_due_at/source UUID ordering to rotate repeatedly busy sources. Update last_considered_at even when the candidate is busy; sources also rotate consideration so a permanently blocked source cannot dominate its workspace. Skip action-required sources and provider-not-yet-eligible work. Selection/consideration commits before entering each scope transaction; recheck under locks. Limit work to one candidate/workspace/tick and bounded50 identity candidates, not unbounded scan-until-success.

Native due processing coalesces the active request and advances next_due_at once to the first regular interval after now; missed intervals yield one catch-up request. Coalescing keeps the active request's captured fences, never silently rewrites them. Revision changes terminalize old work before a replacement. Dispatch claims are expiring bounded CAS fields; after commit enqueue only request UUID. Failed enqueue or Redis loss leaves queued authority and due enqueue_next_at; duplicate ARQ ID is an optimization. Defer busy requests with a small bounded delay so every15s tick does not continuously wake the same source. Maintain a bounded request/receipt recovery page distinct from new due selection.

For n8n, do NOT create scheduled requests from native scheduler. Managed Schedule is the sole periodic trigger; admission transaction checks DB next_due_at and coalesces/advances it once. The durable scanner handles already-created queued n8n manual/retry/continuation requests, which is recovery, not a second schedule owner. Wake writes claim token/expiry before HTTP, includes request UUID and generation/config/backend/template revisions, then releases SQL locks. A timeout or202 leaves the same request queued/running; bounded retry consults receipt/request and sends the same ID. A200 without durable acceptance is only transport acknowledgement. Known unavailable/template mismatch becomes actionable after bounded wake policy; no quota/provider attempt is burned by API-to-n8n wake alone. Keep provider_deadline untruncated: current wake code caps numeric Retry-After at3600 and must instead parse both delta seconds and HTTP date without shortening it.

C4 template upgrade first invalidates backend revision and stops admission, drains/fences current work, installs template with exact applied_template_revision and confirms the old workflow inactive through supported API. Ambiguous deactivation remains reconciliation_required, neither backend admits. Only then apply target backend/revisions and enable schedule. New native source requires no n8n key/workflow. Old token-only templates fail closed; existing HTTP response compatibility does not imply accepting an unfenced old execution.

Every supported managed route carries authenticated source service credential plus request_id, admission_token, source_generation, connector_revision, backend_revision and template_revision: admission, renewal, validate, provider-fetch, RSS, MCP collect, REST collect, crawl, sync, no-changes and failure/release. Path source must equal durable request source; body backend/provider cannot override persisted selection. The request-status GET uses owner WorkspaceContext. Manual collect authenticates owner scope then returns durable request ID, not a user-constructed service capability. Previews that perform provider I/O use admission/quota too. Provisioning validation probes with external provider I/O need a separately owner-authorized bounded probe through the same quota/send gate; plain local schema validation does not consume a provider quota.

The supported REST template invokes shared Python collection, which handles one fenced/debited physical page at a time, pinned public egress preserving TLS/Host, redirects off, <=10 pages/500 records, <=10MiB accepted JSON, <=25MiB decoded transport,30s/request and90s absolute run. No localhost roundtrip for Python worker calls.

Browser crawl dispatch needs special handling: queue_connector_crawl retains request identity in its stage/outbox, but the network executor acquires collection capacity immediately before browser work and binds the existing run lease through an ingestion-owned run-stage admission API. It must not overwrite lease_run_id with collection_lease_token. Keep request running/slot through actual collection acceptance; only then release. Callback includes request/admission/backend fences and exact stage claim. Sidecar performs pre-send quota/fence checks for each external navigation/retry/subrequest or blocks unneeded subresources; if the sidecar cannot enforce this, browser collection is not admitted under this contract. Existing global single-browser gate remains an additional constraint. MCP pagination/tool-call network retries likewise require enforceable owner adapter send hooks; an opaque tool with uncontrolled internal network cannot be advertised as satisfying physical HTTP quota accounting.
